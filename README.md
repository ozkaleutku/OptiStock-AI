# OptiStock AI - Demand Forecast and Safety Stock Module

OptiStock AI is an independent **Artificial Intelligence (AI/ML) Module** designed with a data science focus to be integrated into companies' existing Enterprise Resource Planning (ERP) or MRP systems.

> [!WARNING]  
> **IMPORTANT NOTE (Integration Bridge):**  
> This project is **not** a standalone, full-fledged ERP system (stock entry, invoicing, production recording, etc.). This system is an isolated module that only performs AI analysis and presents the results. A **data bridge (data pipeline / integration software)** must be written by the development team to transfer historical sales, consumption, and product data from the company's main database to this system's database.

## 🚀 Core Features

This module focuses on two main AI analyses:

### 1. Demand Forecast - Prophet Algorithm
- Predicts future product demands by analyzing the company's historical consumption and sales data (time series data).
- Using the **Facebook Prophet** algorithm, seasonality, trends, and past sales holidays/anomalies of products are taken into account.
- Forecast results are processed into the database and visualized in detail to the user with graphs supporting *infinite scroll* on the frontend.

### 2. Safety Stock - LightGBM Algorithm
- Using the **LightGBM** machine learning model; lead times and past demand deviations of products are analyzed.
- The system calculates safety stock levels not only with the AI model but also with traditional statistical methods (King's Formula).
- It offers the user the opportunity to compare the AI's recommendation with the mathematical formula's result, approve the most suitable one (or a manual value), and save it to the system.

---

## 🔗 Data Integration Requirement (Bridge Setup)

For this module to work and for the AI analyses (Prophet & LightGBM) to produce accurate results, the raw data in the main ERP system must be transferred to the **core tables** in the database belonging to this module (via the integration bridge).

**Tables to be Filled by the Bridge Software:**
1. **`item`**: All product, raw material, and semi-finished product cards.
2. **`supplier_item`**: Suppliers of products and average lead times.
3. **`purchase`**: Past purchase orders and delay times (For raw material supply deviation analysis).
4. **`sales_out_history` & `warehouse_movements`**: Past sales and in-warehouse consumption/usage movements (For time series demand forecasting).
5. **`bom` (Bill of Materials):** Content recipes of products. *(Note: If product trees in your company's main system are kept in a "Level" (hierarchical) structure, the `translate.py` module in the project can automatically convert this leveled BOM structure into a format our system can read).*

> [!TIP]
> **Tables That Should Not Be Filled (System Generates Itself):**
> External data **should not** be written to the following tables, which record the forecasts generated by the Prophet and LightGBM algorithms, AI results, and system history. The AI module manages these tables itself:
> - `prophet_table_temporary`, `prophet_table_history`
> - `safety_stock_plan`, `safety_stock_history`, `ss_kings_formula`

> [!NOTE]
> **Customization Need (Warehouse / Production Line Code):**
> Our AI models (LightGBM) analyze the `warehouse_movements` table to understand whether raw materials *actually entered production* (consumption). In the default codes of the system, movements whose target warehouse (`target_warehouse`) starts with the letters **`HK`** are considered "Issue to Production / Consumption".
> If the production warehouse codes of the company you will integrate with are different (e.g., "PRODUCTION", "LINE-1", etc.); you must definitively change this filtering logic by finding the SQL queries that say `target_warehouse LIKE 'HK%'` in the **`backend/AI_ML/lightgbm_algo.py`** and **`backend/AI_ML/lightgbm_backtest.py`** files according to your own company's codes.

## 🧠 Customization of Algorithm Parameters

You can edit the parameters in the following files to change the behavior of the AI models.

### Prophet (Demand Forecast) Parameters

Prophet parameters are defined in **two files**, and both must have the **same values**:

| File | Description |
|-------|----------|
| `backend/AI_ML/prophet_algo.py` *(Lines ~37-42)* | Main module generating next year's forecast |
| `backend/AI_ML/generate_historical_forecasts.py` *(Lines ~34-39)* | Module generating retrospective forecasts for past years |

**Modifiable parameters:**

```python
model = Prophet(
    yearly_seasonality=True,       # Yearly seasonality (True/False)
    weekly_seasonality=False,      # Weekly seasonality (True/False)
    daily_seasonality=False,       # Daily seasonality (True/False)
    changepoint_prior_scale=0.01   # Flexibility of the trend (0.001 - 0.5)
                                   # Small value → flatter trend
                                   # Large value → more sensitive to fluctuations in the data
)
```

> [!WARNING]
> **Always** update Prophet parameters in `prophet_algo.py` and `generate_historical_forecasts.py` files **simultaneously and with the same values**. Otherwise, inconsistency will occur between past forecasts and future forecasts.

---

### LightGBM (Safety Stock) Parameters

LightGBM parameters are defined in **two files**, and both must have the **same values**:

| File | Description |
|-------|----------|
| `backend/AI_ML/lightgbm_algo.py` *(Lines ~117-120)* | Main module generating safety stock forecasts for next year |
| `backend/AI_ML/lightgbm_backtest.py` *(Lines ~121-125)* | Module performing retrospective testing with past data |

**Modifiable parameters:**

```python
model = lgb.LGBMRegressor(
    objective='quantile',    # Loss function ('quantile' is ideal for safety stock)
    alpha=0.85,              # Quantile level (0.0 - 1.0)
                             # High value → higher safety stock recommendation
                             # 0.85 = stock level to meet 85% of demand
    n_estimators=105,        # Number of trees (increasing it increases accuracy, slows down training)
    learning_rate=0.03,      # Learning rate (small value → slower but stable learning)
    num_leaves=31,           # Number of leaves (increasing it increases model capacity, raises overfitting risk)
    verbose=-1,              # Log level (-1 = silent)
    random_state=42          # Fixed seed for reproducibility
)
```

> [!WARNING]
> **Always** update LightGBM parameters in `lightgbm_algo.py` and `lightgbm_backtest.py` files **simultaneously and with the same values**. Otherwise, inconsistency will occur between backtest results and actual forecasts.

> [!TIP]
> **Steps to take after parameter changes:**
> 1. First, re-generate past Prophet forecasts by running `generate_historical_forecasts.py`
> 2. Then, re-run LightGBM backtest by running `lightgbm_backtest.py`
> 3. Finally, generate future forecasts with `prophet_algo.py` and `lightgbm_algo.py`

## ⚙️ Configuration and Installation

For the system to work, **Python**, **Node.js (npm)**, and **PostgreSQL** must be installed on your computer.

### 1. Database and Port Settings (.env)
In the `.env` file located in the project root directory (and in the configurations within the system), there are placeholder texts like `name`, `sifre`, `port no` by default. Before starting up the system, you must **definitively update these variables according to your own environment**:

```env
# Database Configuration
DB_NAME= name          # Database name (e.g., company_db)
DB_USER= postgres      # PostgreSQL username
DB_PASSWORD= sifre     # Your PostgreSQL password
DB_HOST= localhost     # Database address
DB_PORT= port no       # Database port (usually 5432)

# Service Ports
BACKEND_PORT= port no  # Port where Backend API will run (e.g., 8000)
FRONTEND_PORT= port no # Port where Frontend interface will run (e.g., 5173)
```

### 2. Installing Dependencies

**For Backend:**
```bash
cd backend
pip install -r requirements.txt
```

**For Frontend:**
```bash
cd frontend
npm install
```

# OptiStock AI - Talep Tahmini ve Güvenlik Stoğu Modülü

OptiStock AI, şirketlerin mevcut Kurumsal Kaynak Planlama (ERP) veya MRP sistemlerine entegre edilmek üzere veri bilimi odaklı tasarlanmış, bağımsız bir **Yapay Zeka (AI/ML) Modülüdür**.

> [!WARNING]  
> **ÖNEMLİ NOT (Entegrasyon Köprüsü):**  
> Bu proje tek başına çalışan tam teşekküllü bir ERP sistemi (stok girişi, fatura kesimi, üretim kaydı vb.) **değildir.** Bu sistem sadece yapay zeka analizlerini yapan ve sonuçları sunan izole bir modüldür. Şirketin ana veritabanındaki geçmiş satış, tüketim ve ürün verilerinin bu sistemin veritabanına aktarılması için geliştirici ekip tarafından bir **veri köprüsü (data pipeline / entegrasyon yazılımı)** yazılması gerekmektedir.

## 🚀 Temel Özellikler

Bu modül iki temel yapay zeka analizine odaklanmaktadır:

### 1. Talep Tahmini (Demand Forecast) - Prophet Algoritması
- Şirketin geçmiş tüketim ve satış verilerini (zaman serisi verilerini) analiz ederek gelecekteki ürün taleplerini öngörür.
- **Facebook Prophet** algoritması kullanılarak ürünlerin mevsimselliği (seasonality), trendleri ve geçmiş satış tatilleri/anormallikleri hesaba katılır.
- Tahmin sonuçları veritabanına işlenir ve ön yüzde *infinite scroll* (sonsuz kaydırma) destekli grafiklerle kullanıcıya detaylı olarak görselleştirilir.

### 2. Güvenlik Stoğu (Safety Stock) - LightGBM Algoritması
- **LightGBM** makine öğrenmesi modeli kullanılarak; ürünlerin tedarik süreleri (lead time) ve geçmişteki talep sapmaları analiz edilir.
- Sistem sadece yapay zeka modeliyle değil, aynı zamanda geleneksel istatistiksel yöntemlerle (King's Formula) de güvenlik stoğu seviyelerini hesaplar.
- Kullanıcıya, AI'ın önerisi ile matematiksel formülün sonucunu karşılaştırıp en uygun olanı (veya manuel bir değeri) onaylayıp sisteme kaydetme imkanı sunar.

## 🔗 Veri Entegrasyon İhtiyacı (Köprü Kurulumu)

Bu modülün çalışabilmesi ve yapay zeka analizlerinin (Prophet & LightGBM) doğru sonuç üretebilmesi için, ana ERP sistemindeki ham verilerin bu modüle ait veritabanındaki **temel tablolara** (entegrasyon köprüsü ile) aktarılması şarttır.

**Köprü Yazılımı ile Doldurulması Gereken Tablolar:**
1. **`item`**: Tüm ürün, hammadde ve yarı mamül kartları.
2. **`supplier_item`**: Ürünlerin tedarikçileri ve ortalama tedarik süreleri (lead time).
3. **`purchase`**: Geçmiş satınalma siparişleri ve gecikme süreleri (Hammadde tedarik sapma analizi için).

5. **`bom` (Ürün Ağacı):** Ürünlerin içerik reçeteleri. *(Not: Eğer şirketinizin ana sisteminde ürün ağaçları "Level" (hiyerarşik seviyeli) yapıda tutuluyorsa, proje içindeki `translate.py` modülü bu level'lı BOM yapısını otomatik olarak bizim sistemimizin okuyabileceği formata dönüştürebilir).*

> - `safety_stock_plan`, `safety_stock_history`, `ss_kings_formula`

> [!NOTE]
> **Özelleştirme İhtiyacı (Depo / Üretim Hattı Kodu):**
> Yapay zeka modellerimiz (LightGBM), hammaddelerin *gerçekten üretime girip girmediğini* (tüketimi) anlamak için `warehouse_movements` (depo hareketleri) tablosunu analiz eder. Sistemin varsayılan kodlarında, hedef deposu (target_warehouse) **`HK`** harfleriyle başlayan hareketler "Üretime Çıkış / Tüketim" olarak kabul edilmektedir.

## 🧠 Algoritma Parametrelerinin Özelleştirilmesi

Yapay zeka modellerinin davranışını değiştirmek için aşağıdaki dosyalardaki parametreleri düzenleyebilirsiniz.

### Prophet (Talep Tahmini) Parametreleri

Prophet parametreleri **iki dosyada** tanımlıdır ve her ikisi de **aynı değerlere** sahip olmalıdır:

| Dosya | Açıklama |
|-------|----------|
| `backend/AI_ML/prophet_algo.py` *(Satır ~37-42)* | Gelecek yıl tahmini üreten ana modül |
| `backend/AI_ML/generate_historical_forecasts.py` *(Satır ~34-39)* | Geçmiş yıllar için geriye dönük tahmin üreten modül |

**Değiştirilebilir parametreler:**

```python
model = Prophet(
    yearly_seasonality=True,       # Yıllık mevsimsellik (True/False)
    weekly_seasonality=False,      # Haftalık mevsimsellik (True/False)
    daily_seasonality=False,       # Günlük mevsimsellik (True/False)
    changepoint_prior_scale=0.01   # Trendin esnekliği (0.001 - 0.5)
                                   # Küçük değer → daha düz trend
                                   # Büyük değer → verideki dalgalanmalara daha duyarlı
)
```

> [!WARNING]
> `prophet_algo.py` ve `generate_historical_forecasts.py` dosyalarındaki Prophet parametrelerini **her zaman aynı anda ve aynı değerlerle** güncelleyin. Aksi takdirde geçmiş tahminlerle gelecek tahminleri arasında tutarsızlık oluşur.

---

### LightGBM (Güvenlik Stoğu) Parametreleri

LightGBM parametreleri **iki dosyada** tanımlıdır ve her ikisi de **aynı değerlere** sahip olmalıdır:

| Dosya | Açıklama |
|-------|----------|
| `backend/AI_ML/lightgbm_algo.py` *(Satır ~117-120)* | Gelecek yıl için güvenlik stoğu tahminleri üreten ana modül |
| `backend/AI_ML/lightgbm_backtest.py` *(Satır ~121-125)* | Geçmiş verilerle geriye dönük test yapan modül |

**Değiştirilebilir parametreler:**

```python
model = lgb.LGBMRegressor(
    objective='quantile',    # Kayıp fonksiyonu ('quantile' güvenlik stoğu için idealdir)
    alpha=0.85,              # Quantile seviyesi (0.0 - 1.0)
                             # Yüksek değer → daha yüksek güvenlik stoğu önerisi
                             # 0.85 = talebin %85'ini karşılayacak stok seviyesi
    n_estimators=105,        # Ağaç sayısı (artırınca doğruluk artar, eğitim yavaşlar)
    learning_rate=0.03,      # Öğrenme hızı (küçük değer → daha yavaş ama stabil öğrenme)
    num_leaves=31,           # Yaprak sayısı (artırınca model kapasitesi artar, overfitting riski yükselir)
    verbose=-1,              # Log seviyesi (-1 = sessiz)
    random_state=42          # Tekrarlanabilirlik için sabit seed
)
```

> [!WARNING]
> `lightgbm_algo.py` ve `lightgbm_backtest.py` dosyalarındaki LightGBM parametrelerini **her zaman aynı anda ve aynı değerlerle** güncelleyin. Aksi takdirde backtest sonuçları ile gerçek tahminler arasında tutarsızlık oluşur.

> [!TIP]
> **Parametre değişikliği sonrası yapılması gerekenler:**
> 1. Önce `generate_historical_forecasts.py` çalıştırarak geçmiş Prophet tahminlerini yeniden üretin
> 2. Sonra `lightgbm_backtest.py` çalıştırarak LightGBM backtest'ini yeniden çalıştırın
> 3. Son olarak `prophet_algo.py` ve `lightgbm_algo.py` ile gelecek tahminlerini üretin
